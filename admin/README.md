# 本地后台

只在本机运行的 Hugo 博客管理后台。直接读写项目文件，不部署到 GitHub Pages。

## 启动

双击项目根目录的 `start-admin.bat`，或运行：

```bash
npm run admin
```

打开 http://127.0.0.1:4321 。

依赖只有项目已有的 `sharp` 和 Node 内置模块，不需要额外安装。`start-admin.bat` 会自动检查 Node、依赖和端口，并在服务就绪后打开浏览器。

## 功能

- 站点设置：站点名、副标题、描述、主题色、文章字号、作者信息、默认封面、页脚、favicon/头像裁剪。
- 头图中心：首页 Hero 图片/视频、关于/归档/分类/标签/友链/追番/留言页面的头图、文章默认封面。
- 文章：列表、新建、编辑标题/描述/日期/分类/标签/作者/封面/正文、置顶/草稿、删除。
- 页面：关于、友链、追番、留言的标题/头图/正文；归档/分类/标签主要改头图。
- 媒体库：上传图片/视频、预览、复制路径、删除；图片可裁剪、可直接设为头像。
- 外观与组件：Hero 文案、公告栏、社交链接、音乐库（多专辑上传/试听/删除/重建歌单）、Live2D、Utterances 评论配置。
- 预览与发布：Hugo 构建、启动/停止本地预览、Git 状态、发布预检、一键提交并上线。

## 一键发布

后台“预览与发布”里的“提交、推送并上线”会执行：

1. 检查当前分支、线上 `main` 和本地历史是否一致；不一致时停止，避免覆盖线上改动。
2. `git add -A` 并提交当前工作区所有未忽略改动。
3. 先尝试普通 `git push`；如果 GitHub HTTPS 被阻断或远端历史不一致，自动改用 GitHub API 建 blob/tree/commit 并更新 `main`。
4. 等待对应的 GitHub Actions Pages 构建结束，返回提交号、构建链接和线上地址。

走 GitHub API 回退时，远端会生成一个内容相同、SHA 不同的提交；本地 HEAD 与远端 SHA 不一致属于正常现象，下一次发布仍会按文件树校验，不会覆盖线上内容。

命令行也可直接运行：

```bash
npm run publish
npm run publish -- --check      # 只检查，不提交不推送
npm run publish -- --no-wait    # 推送后不等待 Pages 构建
```

也可双击根目录的 `publish-site.bat`。发布期间有跨进程锁，后台和命令行不能同时发布。

## 安全

- 服务只绑定 `127.0.0.1`，没有登录系统，不要把它暴露到公网或局域网。
- 上传只写入 `static/uploads` 或 `static/hero`；覆盖前会备份到 `admin/backups/`（已忽略，不进库）。
- 发布使用本机 Windows 凭据管理器里的 GitHub 凭据；Token 只在后台服务端使用，不会发到浏览器，也不会写入仓库。
- 普通 `git push` 失败时会自动使用 GitHub API 回退；成功后仍会等待 Pages 构建，不会把“已推送”误报成“已上线”。

## 注意

- 后台是功能型界面，不做美化。
- 文章/页面正文是 Markdown，没有富文本编辑器。
- 分类/标签的**单个词条页**没有单独头图，只有分类/标签总览页的头图。
